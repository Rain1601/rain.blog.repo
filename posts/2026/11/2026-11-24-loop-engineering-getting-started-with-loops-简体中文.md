# Loop engineering: Getting started with loops (简体中文)

<blockquote><p>了解 Claude Code 团队如何定义智能体循环，并获得从基于轮次到基于目标、基于时间以及主动式循环的渐进式实践指导，以及每种循环的适用场景。</p></blockquote><h2>循环入门</h2><p>现在有很多关于循环工程或“设计循环”而非直接向编码智能体发出提示的讨论。如果你花些时间在X上试图弄清楚循环究竟是什么，你会看到多种不同的答案。</p><p>在Claude Code团队，我们将循环定义为智能体重复执行工作周期，直到满足停止条件。我们根据以下几个方面将循环分为几种不同类型：</p><ul class="list-disc ml-6"><li class="my-1"><p>它们是如何被触发的</p></li><li class="my-1"><p>它们是如何被阻止的</p></li><li class="my-1"><p>使用的是什么 Claude Code 原语</p></li><li class="my-1"><p>每种任务最适合采用哪种类型。</p></li></ul><p>我们将介绍主要的循环类型、各自的适用场景，以及如何在管理令牌用量的同时保持代码质量。并非所有任务都需要复杂的循环；应从最简单的方案入手，有选择地使用这些模式。</p><h2>回合制循环</h2><p></p><div style="text-align: center; margin: 1rem 0px;"><img src="https://assets.claude.com/84b1736ddd601209f65849c09d999d15bb4ccb96.png" alt="Di" style="width: 100%;" isuploading="false"></div><ul class="list-disc ml-6"><li class="my-1"><p>由：用户提示触发。</p></li><li class="my-1"><p>停止标准：Claude 判断其已完成任务或需要更多上下文。</p></li><li class="my-1"><p>最适合用于：不属于常规流程或日程安排的较短任务。</p></li><li class="my-1"><p>由以下方式管理使用：编写具体的提示词，并利用技能改进验证，以减少交互轮次。</p></li></ul><p>你发送的每个提示词都会启动一个由你逐轮引导的手动循环。Claude 会收集上下文、采取行动、检查工作成果、必要时重复，然后作出回应。我们称之为智能体循环。</p><p>例如，让 Claude 创建一个点赞按钮。它会读取你的代码、进行修改、运行测试，然后交回一个它认为可用的结果。随后你手动检查这项工作，并编写下一个提示词。</p><p>你可以把手动步骤编写成 SKILL.md，从而改进验证环节，让 Claude 能够端到端地检查更多自身的工作。（关于这类自动化该选用技能、钩子还是子代理，请参阅我们的 Claude Code 引导指南。）</p><p>这应当包含一些工具或连接器，让 Claude 能够查看、测量或与结果进行交互。检查越量化，Claude 就越容易进行自我验证。</p><p>例如，在你的 SKILL.md 文件中，你可以指定：</p><pre><code>--- 
name: verify-frontend-change 
description: Verify any UI change end-to-end before declaring it done. 
---

# Verifying frontend changes 
Never report a UI change as complete based on a successful edit alone. Verify it the way a human reviewer would:

1. Start the dev server and open the edited page in the browser.

2. Interact with the change directly. For a new control (button, input, toggle): click it, confirm the expected state change, and screenshot before/after.

3. Check the browser console: zero new errors or warnings.

4. Use the Chrome Devtools MCP, run a performance trace and audit Core Web Vitals.

If any step fails, fix the issue and rerun from step 1 — do not hand back partially verified work.
</code></pre><h2>基于目标的循环（/goal）</h2><div style="text-align: center; margin: 1rem 0px;"><img src="https://assets.claude.com/0c0fab39c03f3bef320d3a017d73ecd8592dd7b6.png" alt="Image" style="width: 100%;" isuploading="false"></div><ul class="list-disc ml-6"><li class="my-1"><p>由：实时手动提示触发。</p></li><li class="my-1"><p>停止条件：达成目标或达到最大轮数。</p></li><li class="my-1"><p>最适合用于：具有可验证退出标准的任务。</p></li><li class="my-1"><p>受管理使用的方式：设定具体的完成标准和明确的轮次上限，“尝试5次后停止”。</p></li></ul><p>有时，单轮交互并不足够，尤其是在处理更复杂的任务时。当智能体能够反复迭代时，表现会更好。你可以通过用 /goal 定义“完成”的标准，来延长 Claude 持续迭代的时间。</p><p>当你定义成功标准后，Claude 就不必自行判断什么算“足够好”而提前结束循环。每当 Claude 试图停止时，一个评估模型会检查你设定的条件，并将它送回继续工作，直到目标达成或达到你设定的轮数上限。</p><p>这就是为什么确定性标准如此有效，例如通过的测试数量或达到某个分数阈值。</p><p>例如：</p><pre><code>/goal get the homepage Lighthouse score to 90 or above, stop after 5 tries.
</code></pre><h2>基于时间的循环（/loop 和 /schedule）</h2><ul class="list-disc ml-6"><li class="my-1"><p>由：指定的时间间隔触发。</p></li><li class="my-1"><p>停止条件：你取消它，或者工作完成（PR 合并、队列为空）。</p></li><li class="my-1"><p>最适合用于：重复性工作，或与外部环境/系统对接。</p></li><li class="my-1"><p>按以下方式管理使用：设置更长的时间间隔，或基于事件而非时间做出响应。</p></li></ul><p>有些智能体工作是重复性的：任务保持不变，只是输入发生变化。例如，每天早上总结 Slack 消息。另一些工作则依赖外部系统，而与外部系统交互的一种简单方式是按固定间隔检查它，并对发生变化的内容作出反应。例如，一个可能收到代码评审或 CI 失败的 PR。</p><p>对于这些情况，你可以在 Claude 以 /loop 方式运行时触发，该方式会按固定间隔重新运行提示词。例如：</p><pre><code>/loop 5m check my PR, address review comments, and fix failing CI</code></pre><p>/loop 在你的电脑上运行，因此如果你关机，它就会停止。你可以通过使用 /schedule 创建一个例程，将循环迁移到云端。</p><h2>主动循环</h2><p></p><div style="text-align: center; margin: 1rem 0px;"><img src="https://assets.claude.com/1df86a865356e379c8eb780517c24479c0f59489.png" alt="Image" style="width: 100%;" isuploading="false"></div><ul class="list-disc ml-6"><li class="my-1"><p>由事件或日程触发，无需实时人工介入。</p></li><li class="my-1"><p>停止条件：每个任务在达成目标后即退出。例程本身会持续运行，直到你将其关闭。</p></li><li class="my-1"><p>最适合用于：定义明确的重复性工作流：缺陷报告、问题分类、迁移、依赖升级等。</p></li><li class="my-1"><p>通过以下方式管理使用：将常规任务路由到更小、更快的模型，并将最强大的模型用于需要判断的决策。</p></li></ul><p>上述原语，连同自动模式和动态工作流（研究预览）等其他 Claude Code 功能，可以组合成一个循环，用于长时间运行的工作。</p><p>例如，要处理收到的反馈，你可以使用：</p><ol class="list-decimal ml-6"><li class="my-1"><p>/schedule(research preview) 运行一个检查新报告的例行程序</p></li><li class="my-1"><p>/goal 明确“完成”的标准，以及记录如何验证该标准的技能</p></li><li class="my-1"><p>用于编排智能体的动态工作流，由智能体对每份报告进行分诊、修复并审查修复结果</p></li><li class="my-1"><p>自动模式，使例程无需停下来请求许可即可运行</p></li></ol><p>综合起来，一个提示词可以是这样的：</p><pre><code>/schedule every hour: check #project-feedback for bug reports. /goal: don't stop until every report found this run is triaged, actioned, and responded to. When fixing a bug, use a workflow to explore three solutions in parallel worktrees and have a judge adversarially review them.</code></pre><h2>维护代码质量</h2><p>循环输出的质量取决于其周围的系统。设计系统时：</p><ul class="list-disc ml-6"><li class="my-1"><p>保持代码库本身的整洁：Claude 会遵循你代码库中已有的模式和约定。</p></li><li class="my-1"><p>给 Claude 一种验证自身工作的方法：通过技能将你和团队所认可的优秀标准编码化。</p></li><li class="my-1"><p>让文档易于获取：框架和库的文档包含最新的最佳实践。</p></li><li class="my-1"><p>使用第二个智能体进行代码审查：拥有全新上下文的审查者偏见更少，也不受主智能体推理的影响。你可以使用内置的 /code-review 技能或 Code Review for Github。编写代码的循环需要相应的检查循环——了解 Anthropic 如何保障 AI 原生 SDLC 的安全。</p></li></ul><p>当个别结果不达标时，不要只停留在修复单个问题上，而要设法将其编码固化，以改进系统，让未来所有迭代都受益。</p><h2>管理令牌用量</h2><p>为了管理令牌用量，循环应当有明确的边界：</p><ul class="list-disc ml-6"><li class="my-1"><p>为任务选择合适的原语和模型：较小的任务不需要多个智能体或循环。有些任务可以使用更便宜、更快的模型。</p></li><li class="my-1"><p>定义明确的成功标准和停止标准：具体说明“完成”是什么样子，以便 Claude 能更快地得出解决方案（但不要过快）。</p></li><li class="my-1"><p>大规模运行前先试点：动态工作流可能生成数百个代理。先在一小部分工作上评估用量。</p></li><li class="my-1"><p>用脚本处理确定性工作：运行脚本比逐步推理更省成本。例如，PDF 技能可以附带一个表单填写脚本，让 Claude 每次直接运行，而不必重新推导代码。</p></li><li class="my-1"><p>不要比你需要的频率更频繁地运行例程：让间隔与你所关注对象的变化频率相匹配</p></li><li class="my-1"><p>查看用量：/usage 命令按技能、子代理和 MCP 细分近期用量，不带参数的 /goal 显示目前的轮数和 token 用量，/workflows 显示每个代理的 token 用量，并且你可以随时停止某个代理。</p></li></ul><p>你的模型选择和努力程度选择是影响循环成本的最大杠杆之一。</p><h2>入门指南</h2><p>总结如下：</p><table style="min-width: 100px;"><colgroup><col style="min-width: 25px;"><col style="min-width: 25px;"><col
